# 有验收标准的优化路线

首版以默认本地语音、零外部请求、明确声音状态和按文章断点为改进点。Read Aloud 已有高亮、分句导航、发音替换和阅读视图，不能将这些基础功能宣传为它没有的能力。

## 1. 更自然的离线中文声音

比较可离线运行且允许分发的中文神经 TTS，优先完整包内运行或用户自选本地服务。评测包括真实 Windows/macOS 的安装大小、首次延迟、CPU/内存、长文吞吐、数字/多音字/中英混读以及盲听结果。必须断网冷启动成功；不能用远程 iframe 或未安装的模型缓存冒充离线。

国内官方云语音可以是独立选项，使用用户自己的凭据，明确费用、请求域名、隐私和失败降级。密钥不得提交 GitHub。默认仍为本地语音；第三方未授权免费接口不作为产品基础。

## 2. 真实扩展与跨平台验收

Windows 的 Chrome/Edge 安装、声音枚举、离线短文与 30 分钟后台播放；macOS 原生 chrome.tts 同项验证。覆盖关侧栏、切页、系统睡眠/唤醒、强制服务工作线程停止、定时停止和进度恢复。记录浏览器版本、声音版本、失败条件和实际网络日志。

## 3. 更强的正文与文档支持

建立中文新闻、公众号、博客、论坛、技术文档的真实页面样本集，测量正文完整率、导航噪声与顺序；只针对证实的问题加适配器。先完成 iframe/open Shadow DOM，再评估 PDF 的本地解析与逐页映射，EPUB 和 OCR 分开评估。PDF/OCR 不应把文件上传给外部服务。

## 4. 可迁移的个人阅读库

用户主动导出/导入本地书架和发音词典，验证版本升级、损坏文件、数据大小和删除行为。跨设备同步需要单独设计认证、加密与冲突处理，不应默认把原文同步到云端。
